1 – 2 · Sources and fetchers

stdlib only — urllib, csv, xml

Both sources are keyless HTTP endpoints, so there is no SDK, no API key and no dependency. The fetchers exist as committed code precisely so the acquisition is reproducible while the data stays out of the repository. 

# scripts/fetch_fred_series.py — the whole mechanism
FREDGRAPH = "https://fred.stlouisfed.org/graph/fredgraph.csv?id={series}&cosd={start}"

def fetch(series: str) -> list[dict]:
    if series not in RESTRICTIONS:          # terms checked before data lands
        raise SystemExit(f"{series} is not in RESTRICTIONS…")
    text = get(FREDGRAPH.format(series=series, start=START.isoformat()))
    return [row for row in csv.DictReader(io.StringIO(text))
            if row[series] != "."]        # holidays skipped, never interpolated

That RESTRICTIONS guard is the whole of DATA_SOURCES.md question 1 made mechanical: an unlisted series is refused rather than silently acquired.

3 · The data directory

11 CSVs · gitignored · ~1 MB

Committing an acquired price series to a public repository is republication (ADR-0044). So data/ is ignored and the fetcher is committed instead — anyone can re-acquire, nobody re-publishes.

4 · Panel and validation

finevents/features/panel.py · finevents/ingest/validation.py

Covariates keep different calendars from gold, so they join as-of: each session takes each covariate's most recent value at or before that date. 

def latest_at(self, when: date) -> float | None:
    """Most recent value at or before `when`; None if the series starts later."""
    position = bisect.bisect_right(self.dates, when)
    return self.values[position - 1] if position else None
    #                                              ^ None, never a default.
    #   An invented value is indistinguishable from real data downstream.

That single choice is worth 646 sessions: a naive date-intersection leaves 2,213, the as-of join leaves 2,859.

5 · Features

finevents/features/volatility.py · pure stdlib, no numpy

σ is the standard deviation of overlapping h-day log returns over the trailing 60 sessions, demeaned, ddof=1. Written without numpy on purpose — the demo is that you can reproduce it in a spreadsheet. 

window   = closes[-60:]
returns  = overlapping_log_returns(window, horizon)   # 60 − h of them
mean     = sum(returns) / len(returns)                # demeaned
variance = sum((r - mean) ** 2 for r in returns) / (len(returns) - 1)   # ddof=1

6 · The two forecasters

chronos-forecasting 2.3.1 · timesfm 2.0.2 · both on torch 2.13.0+cpu

Two libraries, two conventions, one job. Both are thin wrappers that download weights from HuggingFace and run a forward pass. 

# Chronos-2 — returns exactly the quantile levels you ask for, in order
from chronos import Chronos2Pipeline

pipe = Chronos2Pipeline.from_pretrained("amazon/chronos-2")
quantiles, mean = pipe.predict_quantiles(
    [torch.tensor(closes[-60:])],
    prediction_length=5,
    quantile_levels=[0.1, 0.25, 0.5, 0.75, 0.9],
)
# quantiles[0] is [item, horizon, quantile] → (1, 5, 5)
# TimesFM 2.5 — compile once, then forecast
from timesfm import ForecastConfig, TimesFM_2p5_200M_torch

model = TimesFM_2p5_200M_torch.from_pretrained("google/timesfm-2.5-200m-pytorch")
model.compile(ForecastConfig(max_context=512, max_horizon=16,
                             normalize_inputs=True, fix_quantile_crossing=True))
point, quantiles = model.forecast(horizon=5, inputs=[np.asarray(closes[-60:])])
# quantiles is (n, horizon, 10) where index 0 is the MEAN, 1..9 are deciles —
# read index 0 as a quantile and the row looks non-monotonic. Normalise in the wrapper.

One protocol over both. Design §2 defines a Forecaster with a single forecast() method, so the API differences above are absorbed once, in step 2, and never leak into the scoring code. That is the whole reason the protocol exists.

7 · Scoring

Design §4.13 (quantile → bucket) · §4.2 (RPS)

Quantiles become five bucket probabilities, and RPS compares that distribution against the bucket that actually happened. Lower is better, and being wrong by one bucket costs less than being wrong by four — which is why it is RPS and not accuracy.

Running it

every command in the POC, in order

# once
uv sync --group dev --group numeric        # 3m25s, 837 MB
setx HF_HOME "D:\ml-cache\huggingface"     # keep 1.3 GB off C:
uv run pre-commit install

# acquire — safe to re-run, always fetches current
uv run python scripts/fetch_metals_history.py
uv run python scripts/fetch_fred_series.py

# prepare, and print the numbers you can check by hand
uv run python scripts/prepare_gold_poc.py

# the gates
uv run pytest -q
uv run pre-commit run --all-files

Nothing above touches AWS. No credentials, no deploy, no Bedrock. The only network access is two public data endpoints and a one-off weight download.
