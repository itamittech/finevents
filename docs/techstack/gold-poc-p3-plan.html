Two models, one gate, two evaluations

P3 installs Chronos-2 and TimesFM, proves they are deterministic, and then splits into two evaluations that answer different questions. Neither substitutes for the other.

Step by step

what each step produces, and how you check it

StepProducesYour check
1 · install chronos-forecasting and timesfm[torch] in the lockfile; 1.34 GB of weights cached on D: Measured install size and first-forecast latency, printed — not estimated
2 · wrappers finevents/numeric/ — two classes behind the Design §2 Forecaster protocol Unit tests; the import-boundary lint stays green
3 · gate A test that runs each model twice on identical input Byte-identical output, or P3 stops here
4 · buckets Quantiles → five probabilities, summing to 1 Tail rule applied identically to both models and recorded with the forecast
A · sealed predictions/<date>.json, committed before the outcome exists The commit timestamp versus CBR's publication time. Anyone can verify it
B · rolling A table of RPS by rung and horizon, full history and 2026 separately Pick a day, work out the realised bucket by hand, check the stored score

Why both. The sealed prediction is n = 1 — it can never show that the models have skill. The rolling evaluation has n = 145 but is only as believable as the claim that nothing leaked. Together they cover each other: one proves the pipeline cannot cheat, the other measures whether it is any good.

What could go wrong

named in advance, so a surprise is a finding and not a scramble

RiskWhat it would mean
Determinism fails The most likely real problem. If seeding doesn't fix it, REQ-507 is unmet, Lane A replay is meaningless, and that changes the project's design — not just this POC. Better to hit it at step 3 than at step B
Covariate API differs from docs Chronos-2 advertises native covariates and TimesFM uses xreg; if either rejects 10 channels, the covariate rungs shrink and the plan says so rather than quietly dropping them
Models lose to climatology Not a failure. Gold at daily resolution is close to a random walk, and a foundation model failing to beat 62.5%-flat is a real and publishable finding. It arrives before nine-tenths of the system is built on the opposite assumption
145 days is thin True, and stated up front. It bounds what can be claimed; it does not invalidate the measurement
CBR timing The publication lead has to be confirmed empirically before the sealed forecast, or "the first unpublished session" is a guess

Nothing in P3 touches AWS. No deploy, no Bedrock, no credentials. It runs on the laptop, and the only network access is downloading weights from HuggingFace and reading CBR and FRED — the same two sources already in use.
